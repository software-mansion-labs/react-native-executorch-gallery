When it needs a moment.

Model loading and inference are separate states. Loading stays in the selected model’s row. During object detection, keep the input image visible, remove stale boxes, and show an honest indeterminate indicator. The timings and images below are illustrative.

Keep layout and image controls in place. Disable conflicting actions until the operation completes. Show latency only with the completed result, and offer cancellation only if the underlying task can actually stop.

The direction

Less chrome. More room.

What to borrow from Gemini mobile

Generous breathing room, a quiet model selector, large content-led cards, and a composer close to the thumb. Keep the natural assistant response layout and soft bottom glow. Use translucency locally where it helps establish depth.

What to borrow from TypeGPU Kit

Neutral graphite instead of navy, precise result metrics, and an identity built around the actual technology. Keep these details quiet. The main screens do not need decorative animation, a point cloud, or more badges.

Avoid making every surface glass, importing a desktop sidebar, or turning the entire gallery into a chat interface. Each demo should retain a clear, useful dedicated screen.

Other viable directions

Soft studio: Gemini-led, warm white, pale blue, bigger imagery. Most approachable; less distinctive as a developer showcase.

Technical lab: TypeGPU-led, dense instrumentation, cyan lines, tiny mono labels. Strong identity; easier to overdo on a phone.

Recommended blend: the mobile assistant’s spaciousness with a little technical precision. System sans for reading; monospace only for model metadata and measurements. Support both system themes with equal care.

Use neutral graphite and white, with a muted blue accent only on the primary action. In light mode use neutral surfaces and a darker blue accent. Keep segmentation colors in the results.

Interaction recommendations

Feel better at the moments that matter.

Moment Recommendation Implementation boundary
Discover a demo Show three simple entry points, then navigate to a dedicated searchable catalogue. Keep technical task names searchable as secondary labels. Bring chat and speech above the current seven vision rows. Extract task data and home cards from src/app/index.tsx. No new navigation tabs until there are useful distinct destinations.
First run One clear “Download & prepare” action with model download size where known, then separate downloading, preparing, and ready states. Offer a real bundled sample so users can get a result quickly. Explain that first use needs a download. Extend TaskHeader and StatusBanner. Use real resource metadata; progress must not imply measured inference progress. Keep disk deletion in the model sheet, separate from unloading.
Press / choose A small 120–160 ms press response; a light selection haptic on task selection and useful discrete selections. Standard navigation usually needs visual feedback only. Use existing Reanimated and shared controls. Add expo-haptics through one shared, best-effort feedback hook. Keep inference independent of haptic promises.
Record / finish One clear haptic when recording starts or stops; one soft completion cue for a long task; error feedback paired with actionable text. No haptics per streamed token, waveform update, camera frame, or detection. For Android use the platform haptic APIs documented by Expo. Some iOS recording/camera states suppress haptics; visual state remains authoritative. Verify on physical devices.
Wait / cancel Show meaningful text (“Preparing response”, “Listening”, “Generating image”) and a stable Stop action for operations the library can cancel. Transition from empty to result with a short fade. Keep actual latency as a small result caption. Shared viewports and action controls. Do not simulate percent completion for inference or fake streaming. Keep the layout steady during state changes.
Read / type Make the composer grow from one line to a capped height; move examples into the empty state. Show assistant text on the page and user messages in a soft bubble. Auto-follow streaming only while the reader is near the bottom. PromptInput and ChatViewport; reusable scroll-follow logic belongs in a documented hook.
Access / comfort At least 44 pt iOS / 48 dp Android action targets, scalable text, explicit icon labels, reduced motion, and status text alongside color. Keep the viewport flexible at large font sizes. Central tokens plus shared components; verify keyboard, safe areas, screen reader labels, and both themes. The mockups are visual studies, not accessibility sign-off.
Architecture review

Keep the examples easy to lift.

The existing pattern is worth preserving

15 task routes. Screens choose a model, call an ExecuTorch hook, hold input/results, and invoke one task handler. ScreenWrapper unmounts task content when unfocused; TaskScreen owns layout; TaskHeader, StatusBanner, and shared inputs own the chrome. Task-specific overlays own detection, segmentation, pose, OCR, and rendering. Audio and image lifetimes already use helper hooks.

The largest presentation outlier is the home route: task registry, sections, cards, and styles share one file. Split those before adding discovery interactions. The task-screen skill requires minimal screens, documented custom hooks, and theme tokens.

Recommended implementation order

  1. Foundation: unify theme tokens and root navigation colors; add typography, interaction, and motion tokens. Keep the Software Mansion identity.
  2. Discovery + one vertical slice: build the home and chat direction, including first-download, ready, streaming, error, keyboard, and large-text states.
  3. Shared task shell: simplify model status, move model controls into the sheet, improve empty states and add useful sample inputs.
  4. Roll out + tune: migrate vision and audio, add selective haptics, and profile on real devices while inference runs. Capture before/after screenshots.
